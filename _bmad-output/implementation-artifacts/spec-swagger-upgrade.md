## Intent

**Problem:** The project uses `drf-yasg` (OpenAPI 2.0, largely unmaintained) for API documentation; it is gated by `IsAdminUser` (checks `is_staff`) rather than `is_superuser`, and the existing API views lack inline schema annotations.

**Approach:** Replace `drf-yasg` with `drf-spectacular` (actively maintained, OpenAPI 3.0), add a custom `IsSuperUser` permission that gates all swagger endpoints, and annotate every DRF view with `@extend_schema` for accurate auto-generated documentation.

## Boundaries & Constraints

**Always:**
- All swagger/schema endpoints (`/swagger/`, `/redoc/`, `/swagger/schema/`) must require `request.user.is_superuser == True`.
- All 6 existing API endpoints must appear in the generated schema: `GET /events/api/v1/events/`, `GET /events/api/v1/events/future/`, `POST /events/api/v1/events/create/`, `GET /events/api/v1/organizers/search/`, `GET /events/api/v1/speakers/search/`, `GET /places/api/v1/places/search/`.
- `requirements.txt` must be regenerated via `pip-compile` inside Docker after updating `requirements.in`.

**Ask First:**
- If pip-compile fails due to dependency conflicts between drf-spectacular and any other installed package.

**Never:**
- Change any existing API endpoint URLs, response shapes, or permission classes on the API views themselves.
- Add a `sidebarUrls` or external UI CDN — keep the default drf-spectacular Swagger UI (bundled).
- Keep `drf_yasg` in `INSTALLED_APPS` after migration.

## Design Notes

drf-spectacular's `SpectacularAPIView` (raw schema), `SpectacularSwaggerUIView`, and `SpectacularRedocView` each accept `permission_classes` directly, so no middleware or global override is needed. The `IsSuperUser` class goes in `desparchado/permissions.py` (project-wide module) following the existing convention of project-level utilities in `desparchado/`.

`SPECTACULAR_SETTINGS` minimum viable config:
```python
SPECTACULAR_SETTINGS = {
    'TITLE': 'Desparchado API',
    'DESCRIPTION': 'API for discovering cultural and educational events in Colombian cities.',
    'VERSION': 'v1',
}
```

`@extend_schema` on a CBV class applies to all HTTP methods; use it on the class for `ListAPIView`/`CreateAPIView`, and on the `get()` method for `APIView` subclasses that only implement GET.
